1. Project Mission — Stated vs Actual

Stated mission (README): "A top-down arena shooter built with Godot 4.3 and C# (.NET 8). Fight waves of enemies across 4 hero classes; environmental destruction escalates threat via the Collateral Karma system."

Actual state: A horde / top-down arena shooter (Vampire Survivors / Brotato / Hades-like) with 4 heroes, 10 enemy types, Weibull wave-spawning curve, 2000-enemy cap, 5s breather between waves, boss every 300s, XP-driven level-up into a 20-perk upgrade menu, and a Collateral Karma threat escalation.

Success criteria (how we know it's working)

  • Player survives escalating waves and builds score.
  • Player levels up and picks meaningful perks.
  • Threat escalates via environmental destruction (Collateral Karma).
  • Enemy mutators stack as threat rises.

Stated vs actual gap

  • No tutorial / onboarding. New players are dropped into Wave 1 with 4 opaque heroes and 20 cryptic perks.
  • No difficulty selector. One fixed curve (Weibull + karma threat + stacking mutators) — novices cannot soften the challenge.
  • No perk transparency. Perks show names only; 17 of 20 perks are no-ops in UpgradeMenu.ApplyPerk().
  • No practice / sandbox mode. Permadeath GameOver gives novices no room to experiment.

R1 · Guided Tutorial / "First Wave" Onboarding Mode

Impact: High Effort: ~3–4 days (1 dev) Gate: New GameState.Tutorial [T1 Hades GDC · T2 VS/Android Police · T2 Brotato/Superjump · T3 VS Wiki]

Problem: New players get no instruction — controls, dodge, abilities, and the level-up/perk flow are never explained; Wave 1 already spawns mixed enemies at full speed.

What (grounded): No dedicated tutorial level — Hades / Vampire Survivors / Brotato all use learn-by-doing with minimal UI. Make Wave 1 the guided first experience: soft spawns (1–3 slow Drones, one at a time), teach 3 verbs in the first 60s (move/dodge, auto-attack, collect XP), auto-pause at first level-up (~5 XP, ~40–60s in), on-screen control prompts, then forced-choice 3-perk UpgradeMenu.

Endpoint / control: MainMenu.StartTutorial() → sets tutorial flag, loads game scene → GameManager.StartTutorial() → enters GameState.Tutorial. New scripts/ui/Tutorial.cs { enum Step{Move,Attack,Dodge,Ability,LevelUp,Done}; SpawnNextDrone(); ShowPrompt(Step); MarkStepDone(Step) } + scenes/ui/Tutorial.tscn (center-screen gold prompt label, font_size 30, outline; progress dots "Step X of 5").

R2 · Difficulty Selector (Easy / Normal / Hard)

Impact: High Effort: ~2–3 days (1 dev) Gate: GameManagerState.Difficulty enum + GetSettings() [T2 Inverse Hades God Mode · T2 Access-Ability · T3-4 Brotato Wiki · T4 VS Nexus]

Problem: A single fixed curve (Weibull wave intensity + CollateralKarma threat every 10 destructions + stacking EnemyMutatorSystem mutators) punishes novices. Destroying the environment raises threat and strengthens enemies — novices snowball into an unwinnable state within minutes.

What (grounded): Two orthogonal levers (per Brotato/Vampire Survivors): (a) spawn/density curve via Weibull multiplier, (b) per-enemy stats via HP/damage multiplier. Plus threat interval, mutator scale, XP multiplier, breather seconds. Optional Hades-style player damage-resistance toggle (20% → 80% cap, +2%/death) that doesn't block progression. Persisted in save, chosen from MainMenu dropdown.

Endpoint / control: GameManagerState.SetDifficulty(Difficulty) + GetSettings(Difficulty) → DifficultySettings{EnemyCountMultiplier, EnemyHealthMultiplier, EnemyDamageMultiplier, ThreatInterval, MutatorScale, XpMultiplier, BreatherSeconds, PlayerDamageResistance}. WaveManager.BeginNextWave() reads GameManager.Instance.DifficultySettings. EnemyMutatorSystem.ApplyMutators(enemy, threatLevel, mutatorScale).

Sources: [T2] Inverse Hades God Mode — https://www.inverse.com/gaming/hades-god-mode-interview · [T2] Access-Ability — https://access-ability.uk/2022/04/25/hades-god-mode-is-a-great-approach-to-difficulty/ · [T3-4] Brotato Wiki Danger Levels — https://brotato.fandom.com/wiki/Danger_Levels · [T4] VS Nexus curse — https://www.nexusmods.com/vampiresurvivors/mods/120

R3 · Perk Transparency + Practice / Sandbox Mode

Impact: Critical Effort: ~4–5 days (1 dev) Gate: fix ApplyPerk() for all 20 perks [T2 Android Police VS · T3 VS Wiki · T2 Digital Trends Brotato · T3 Hades 2 Wiki · T3 kokutech]

Problem (two parts): (1) Perk choices are meaningless — ApplyPerk() implements only DamageUp (commented no-op), SpeedUp, and MaxHealthUp; the other 17 perks do nothing. (2) No safe place to experiment — permadeath GameOver on first death gives novices no room to learn.

What (grounded): Perk cards show icon + name + explicit one-line effect line (+ synergy tag badge if player holds a prerequisite); 3 options (Galante's sweet spot); forced choice by default (skip/reroll gated, never free); synergies surfaced via tags not spelled-out optimal builds. Fix ApplyPerk() to implement all 20 perks with real effects. Add Sandbox mode: no waves, no GameOver; spawn dummies, god mode, try any hero/perk, reset stats.

Endpoint / control: MainMenu.OpenSandbox() → loads Sandbox scene; Sandbox.SpawnDummy(Vector2?), Sandbox.SetGodMode(bool), Sandbox.ApplyPerk(PerkType), Sandbox.ResetHero(). New scripts/maps/Sandbox.cs + scenes/maps/Sandbox.tscn (toolbar: Spawn Dummy / Toggle God Mode / Apply Perk dropdown / Reset Hero / Back to Menu). UpgradeMenu.PerkDescription(PerkType) + ApplyPerk() all 20 perks.
