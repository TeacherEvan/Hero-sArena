🎯 Project Mission

Stated Mission

A top-down arena shooter built with Godot 4.3 and C# (.NET 8). Fight waves of enemies across 4 hero classes; environmental destruction escalates threat via the Collateral Karma system. [README.md, project.godot config/description]

Success Criteria

  • Survive escalating waves of enemies with rising threat level.
  • Meaningful build variety via 20 perks across 4 hero classes.
  • Responsive twin-stick combat with i-frame dodge and class abilities.
  • Headless-testable pure logic (xUnit) + Godot headless gate.

Gap Analysis (Stated vs Actual)

BAD

Late-game difficulty decays. The Weibull wave curve (WaveFormulas.cs:26-29) peaks at ~wave 5 then decays toward zero, so late waves get easier instead of harder — contradicting "escalating threat." Vampire Survivors maintains pressure via time-based HP scalars that make difficulty catch up (Tier 3: Arcade Artificer). Reddit r/gamedesign flags reverse/decaying difficulty curves as bad design (Tier 4).

Source: scripts/core/WaveFormulas.cs:26-29; Arcade Artificer Substack (Tier 3); Reddit r/gamedesign (Tier 4)
BAD

Perk synergies are tags only. All 20 perks carry a SynergyTag but no synergy mechanics exist — every perk is a flat stat multiplier (PerkSystem.cs:13-35). Nine perk effects are declared but never consumed at runtime (HealthRegen, ExplosiveRounds, LifeSteal, CritChance, SlowOnHit, BurnOnHit, FrostAura, ThornArmor, DoubleJump). Hades proves prerequisite-driven perk pairs (Duo Boons) create emergent power and thrilling discoveries (Tier 2: TheGamer, Hades wiki).

Source: scripts/core/PerkSystem.cs:13-87; scripts/core/HeroStats.cs:10-29; TheGamer Hades Duo Boons (Tier 2)
BAD

No meta-progression between runs. Each run starts from baseline; nothing is kept after death. Vampire Survivors' meta-progression (gold kept on death, permanent stat shop) eliminates "zero progress" runs and drives immediate retries (~2.5× damage / 2× health cumulative; Tier 3: Arcade Artificer).

Source: Arcade Artificer Substack (Tier 3)
GOOD

Core loop is complete. Wave spawning (fixed per PR #18), mutators applied at spawn (fixed per PR #19), AoE damage works (fixed per PR #18), 4 hero classes each with Attack/Dodge/Ability, Collateral Karma threat escalation, difficulty selector persisted to user://settings.cfg.

Source: scripts/core/WaveManager.cs, EnemyMutatorSystem.cs, Atlas.cs/Zephyr.cs/Synapse.cs/Volt.cs

📊 Implementation Optimality

Algorithm Fit

GOOD

Weibull intensity curve for wave spawning is an appropriate choice for horde-shooter density ramps (rises from 0, peaks ~wave 5). SpatialHashGrid O(1) queries are optimal for collision-heavy arena combat.

Source: scripts/core/WaveFormulas.cs, SpatialHashGrid.cs
BAD

Weibull curve decays after wave 5 — late waves get easier. RoR2 shows difficulty coefficient should scale with stages/time, not taper (Tier 2: riskofrain2.wiki.gg). Brotato's Endless Factor shows late-game escalation via additive HP multipliers (Tier 2: Brotato Wiki).

Source: Brotato Wiki Endless Mode (Tier 2); RoR2 Difficulty (Tier 2)

Computational Complexity

GOOD

Spawn capped at MAX_ENEMIES=2000 with MAX_SPAWNS_PER_FRAME=20 throttle — O(cap) per frame, bounded. Flow field on background thread at ~4 Hz avoids main-thread stalls.

Source: WaveManager.cs:12-15, FlowFieldPathfinder.cs

Resource Usage

GOOD

Object pool eliminates runtime GC pressure from projectile/decal instantiation.

Source: ObjectPoolManager.cs

Alternative Approaches

  • Replace decaying Weibull late-game with additive per-wave HP/damage multiplier (RoR2/Brotato pattern).
  • Replace flat per-perk stats with prerequisite-driven synergies (Hades Duo Boons pattern).

Scalability (10x Load)

WARN

2000 enemy cap is a hard backstop; at 10x spawn demand the spawn loop runs zero times once full (WaveFormulas.cs:48-50). Acceptable as safety valve but late-wave intensity plateaus.

Source: WaveFormulas.cs:38-51

💡 Recommendations

Prioritized, actionable feature recommendations. Each includes what to build, why, effort, and the concrete source.

High
R1 — Replace decaying late-game Weibull with sustained/escalating intensity
Why: Late waves get easier, contradicting the "escalating threat" mission. Vampire Survivors keeps pressure via time-based HP scalars that make difficulty catch up (Tier 3: Arcade Artificer). RoR2 scales difficulty coefficient with stages/time (Tier 2). Brotato's Endless Factor adds multiplicative HP/damage escalation past wave 20 (Tier 2: Brotato Wiki).
What: Add a per-wave HP/damage multiplier that scales with wave number (e.g., +1× base HP per boss cycle, additive not compounding). Keep the 2000 enemy cap as hard backstop. Add an optional "Curse"-style toggle trading enemy HP/speed/density for gold/XP. Expose a visible threat-level meter driven by waves cleared (RoR2 HUD bar pattern).
Endpoint / CLI: Modify scripts/core/WaveFormulas.cs (CalculateWaveEnemyCount) and scripts/core/WaveManager.cs (BeginNextWave spawner); add threat-meter UI to scripts/ui/HUD.cs.
Interactive Control: Difficulty toggle "Curse mode" in MainMenu difficulty selector; threat-level progress bar on HUD.
Effort: ~2-3 days (WaveFormulas + WaveManager + HUD threat meter).
Source: scripts/core/WaveFormulas.cs:26-51; Arcade Artificer Substack (Tier 3); RoR2 Difficulty (Tier 2); Brotato Wiki Endless Mode (Tier 2)
High
R2 — Implement real perk synergy combos (prerequisite-driven emergent effects)
Why: Perks carry SynergyTag but no synergy mechanics; nine effects are declared but unconsumed. Hades' 28 Duo Boons show prerequisite-driven perk pairs create emergent power and thrilling discoveries (Tier 2: TheGamer). Vampire Survivors' weapon evolutions (max level + passive prereq) are a discrete synergy lever (Tier 2: teemo.dev).
What: Add 4-6 two-perk synergy triggers with emergent results (e.g., FrostAura + SlowOnHit → brief freeze; BurnOnHit + ExplosiveRounds → exploding burning-corpse chain). Gate each emergent perk behind two base perks already taken. Show synergy hints on perk cards when one perk away from unlocking. Consume the nine dead effects (HealthRegen regen tick, ExplosiveRounds projectile flag, LifeSteal heal-on-kill, CritChance roll, SlowOnHit/BurnOnHit/FrostAura/ThornArmor/DoubleJump consumers).
Endpoint / CLI: Extend scripts/core/PerkSystem.cs ApplyPerk with a synergy table; add synergy hints to scripts/ui/UpgradeMenu.cs perk cards; wire consumers in hero attack/dodge/take-damage paths (HeroBase.cs, Atlas.cs, Zephyr.cs, Synapse.cs, Volt.cs).
Interactive Control: Perk-card synergy badges/hints in UpgradeMenu; "evolution" perk flagged in offer pool when prerequisites met.
Effort: ~4-5 days (synergy table + dead-effect consumers + UI hints).
Source: scripts/core/PerkSystem.cs:13-87; scripts/core/HeroStats.cs:10-29; Hades Duo Boons (Tier 2); Vampire Survivors weapon evolutions (Tier 2)
Medium
R3 — Add meta-progression between runs (gold kept on death, permanent stat shop)
Why: No meta-progression means every run starts from zero — "zero progress" runs. Vampire Survivors' meta-progression (gold kept on death, escalating stat shop at 1.1^TotalBought pricing, full respec) eliminates this and drives immediate retries (~2.5× damage / 2× health cumulative; Tier 3: Arcade Artificer). Hades Mirror of Night shows Darkness + Chthonic Keys gating with refundable unlocks, max achievable in ~50 runs (Tier 2: TheGamer).
What: Award run currency (scrap) based on kills/destruction/wave reached, kept after death. Spend in a main-menu permanent node tree for starting-stat bonuses (+max health, +move speed, +starting damage) and hero unlocks. Add slow tiny-stat "egg" track for long-term accumulation. Include full-respec button.
Endpoint / CLI: New scripts/core/MetaProgressionState.cs (Godot-free, headless-testable) + scripts/ui/MainMenu.cs meta-progression screen; save to user://meta.cfg via ConfigFile (mirroring MenuDifficultyState pattern).
Interactive Control: Meta-progression node tree in MainMenu; scrap currency display on HUD/run-end screen; respec button.
Effort: ~5-6 days (state + save/load + menu screen + HUD).
Source: Arcade Artificer Substack (Tier 3); Vampire Survivors PowerUp shop (Tier 2); Hades Mirror of Night (Tier 2); scripts/core/MenuDifficultyState.cs (existing pattern)
Medium
R4 — Re-apply mutators as threat rises (EnemyMutatorSystem.OnThreatChanged)
Why: Mutators applied once at spawn only; rising threat never re-mutates live enemies. OnThreatChanged is an empty stub. Splitting mutator commented out. This wastes the threat system's escalation potential.


What: Implement OnThreatChanged to re-apply stacking mutators to live enemies as threat increases (capped per-mutator to avoid runaway). Un-comment and implement the splitting mutator as a high-threat elite wave mechanic (Brotato: +1 elite per 10 waves).
Endpoint / CLI: Implement scripts/systems/EnemyMutatorSystem.cs OnThreatChanged(int) + ApplySingleMutator extension for live enemies; add splitting mutator.
Interactive Control: Threat-level-driven mutator intensity visible on HUD threat meter.
Effort: ~2-3 days.
Source: scripts/systems/EnemyMutatorSystem.cs:34-78; Brotato Danger Levels (Tier 2)
